# Syntax

Sticks Lite source files use the `.slite` extension and one statement per line.

## File shape

```slite
DEFINE MAX_SCORE = 100

score = 87

if score >= 80:
    say "Passing"
```

Top-level statements run from top to bottom. Function definitions are collected
before top-level statements run.

## Comments

Line comments start with `#`.

```slite
# This line is ignored.
say "Start" # This part is ignored.
```

Block comments use `/*` and `*/`.

```slite
/*
This block is ignored.
*/
say "Done"
```

Comment markers inside text stay part of the text.

```slite
say "# not a comment"
say "/* not a comment */"
```

Nested block comments are not supported.

## Blocks and indentation

Block-opening statements end with `:`. The block body starts on the next line
and is indented.

```slite
if True:
    say "inside"
say "outside"
```

Tabs and spaces cannot be mixed for indentation. Four spaces per level are
recommended.

## Keywords

```txt
DEFINE if orif otherwise repeat times loopif foreach in
break continue new return True False null and or not div
say ask attempt when error
```

Keywords are case-sensitive.

## Statement forms

| Form | Example |
| --- | --- |
| Output | `say "Hello"` |
| Input expression | `name = ask "Name?"` |
| Assignment | `score = 10` |
| Constant | `DEFINE MAX_SCORE = 100` |
| Conditional | `if score > 0:` |
| Counted loop | `repeat 3 times:` |
| Conditional loop | `loopif count > 0:` |
| Collection loop | `foreach item in items:` |
| Function | `new double(value):` |
| Return | `return value` |
| Error handling | `attempt:` and `when ValueError:` |

## Common syntax errors

| Error | Cause |
| --- | --- |
| Missing colon | A block opener such as `if`, `repeat`, or `new` needs `:`. |
| Bad indentation | A block body is not lined up with earlier indentation. |
| Unfinished string | A quoted text value is missing its closing quote. |
| Invalid `orif` | `orif` must directly follow an `if` or another `orif`. |
| `otherwise` without `if` | `otherwise:` must finish an `if` chain. |
